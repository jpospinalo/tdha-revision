## Module interfaces

The outputs of `data.py → run_experiment.py`, `run_experiment.py → compile_results.py`, and `run_queue.py → run_experiment.py` match the inputs each next stage expects.

## Data processing

ROI time series load correctly, subjects keep their metadata, site TRs are handled, and the resulting structures stay consistent through the pipeline.

## Connectivity

Static produces one matrix per subject over the whole series; dynamic produces window sequences in temporal order, from physically-defined windows. Both are checked for symmetry, diagonal, and value range. The Ledoit-Wolf shrinkage estimators (`partial`, `shrunk`) are checked in `verify_setup.py` for shape, finiteness, and range, same as the Pearson-based ones.

`ordered_scaled`, `permuted_scaled`, and `tangent` are checked in `verify_setup.py` for two additional properties, not just shape/finiteness: that the fit-only statistic (mean/sd for the scaled variants, the geometric reference for `tangent`) reproduces the expected value on `fit`, and — the leakage check — that perturbing subjects outside `fit` does not change the output for subjects inside `fit`. This was also verified against real NYU/NeuroIMAGE data (not just synthetic fixtures) when these representations were added, together with a bit-exact regression check confirming every historical representation's output tensor is unchanged.

## Windowing

Seconds convert to samples correctly, overlap is applied consistently, different TRs yield equivalent physical windows, and both rectangular and Gaussian windows work.

## Training

Partitions stay isolated; the inner partition is used only for epoch selection and the outer fold only for the final evaluation; class weights come from the training partition alone; and every registered architecture builds with a single sigmoid output.

`verify_setup.py --full` trains exactly twice: `val_loss` and `val_bce` with BrainNetCNN, same everything else, sharing a single root directory that is cleaned once (not once per monitor) so the preflight is repeatable without leftover state. There is no third, generic smoke run — the earlier `/tmp/verify_setup` lstm smoke was dropped because it wasn't repeatable without `--overwrite` and its only real job, checking what monitor is active when `--early-stopping-monitor` is omitted, is now a pure parser check (`run_experiment.build_parser().parse_args([])`, asserting `early_stopping_monitor == "val_loss"` and `early_stopping_min_delta == 1e-5`) that needs neither TensorFlow nor a training run. Each of the two BrainNetCNN runs is checked beyond the exit code: `config.json` records `config_schema_version=4`, the requested monitor, `min_delta`, and a non-null `early_stopping_ab_hash`; `history.csv` is non-empty with `bce`/`inner_val_bce`/`loss`/`inner_val_loss` and no NaN/inf; `metrics_train.csv` exists with the same row count as `metrics_val.csv` and the same schema-4 metadata; `metrics_val.csv` carries `early_stopping_monitor`/`best_monitor_value`/`restored_monitor_value`; `best_epoch` falls within `[1, n_epochs]` and the history value recorded at that epoch matches `best_monitor_value`; `fit`/`inner_val`/`outer_val` never share a subject within a fold; and `predictions_val.csv` covers every subject exactly once per repetition. Earlier versions of this check derived `best_epoch` as `argmin` of the monitored series and called that a confirmation of which weights `EarlyStopping` restored — that was circular (it re-derived the same assumption the executor made, rather than testing it) and has been replaced: `best_epoch`/`best_monitor_value` now come from the `EarlyStopping` instance itself (`.best_epoch`/`.best`, not `np.argmin` — see `methodology.md`), and the actually-restored weights are checked independently by re-evaluating the model on `inner_val` right after `fit()` (`restored_monitor_value`), which is compared against `best_monitor_value` as the non-circular proof — `run_experiment.py` itself now enforces this match (`RuntimeError` before the outer fold is used, see `methodology.md`), and the audit here re-confirms it from the written artifacts. The two runs are additionally checked to share `split_fingerprint` and `early_stopping_ab_hash` while differing in `config_hash` — proof they are identical except for the monitor. This audit only checks the A/B-specific `config.json` fields itself (schema version, requested monitor, `min_delta`, non-null `early_stopping_ab_hash`); everything else — the history/metrics/predictions/folds checks described above — is delegated to `compile_results.validate_run_artifacts()`, the same function `collect(strict=True)` and the notebook's export gate call, so there is one place that defines what a valid schema-4 run looks like, not two copies that can drift apart.

Without retraining, the same two runs feed a compiler-integration check: `compile_results.collect(root, strict=True)` must return exactly one row per monitor with no duplicates, `compile_results._check_early_stopping_ab()` must accept that real pair, and two in-memory variants built from it — a duplicated `val_loss` row (no `val_bce`) and a row with `early_stopping_ab_hash` overwritten — must both be rejected. This exercises the same guard `--stats --stats-by early_stopping_monitor` relies on, without spending a second round of training to do it.

`compile_results.validate_run_artifacts()` — the function `collect(strict=True)` calls on every `config_schema_version >= 4` run before compiling it — is itself checked with hand-written CSV fixtures, without training or importing TensorFlow, so this runs even without `--full`. It used to be a private function, `_validate_schema4_artifacts()`, called only from `collect()`; it is now public and self-contained (it reads `config.json` itself if the caller doesn't already have it parsed), so `verify_setup.py`'s audit and the notebook's pre-download/pre-push gate call the same function `collect()` uses, instead of each keeping its own partial copy of the checks.

An earlier version of this function required only a subset of columns (`predictions_val.csv` and `folds.csv` had no required columns at all) and checked finiteness via `frame[present].stack()`, which drops `NaN` by default before `np.isfinite()` ever sees it — both were reproduced with a deliberately corrupt schema-4 result (`best_monitor_value=NaN`, missing structural columns) that the old function waved through and `collect(strict=True)` accepted. The fix requires `fold`/`repeat`/`subject_id`/`split`/`epoch`-style structural identifiers across all five artifacts (not just the three that already had a `required_by_file` entry) and replaces `stack()` with `frame[present].apply(pd.to_numeric, errors="coerce").to_numpy(dtype=float)`, which keeps every position — including one that started as `NaN` or as non-numeric text — so `np.isfinite()` actually audits it.

Beyond that column-presence and finiteness check, `validate_run_artifacts()` also checks *consistency between* the five files, not just each one on its own: `metrics_train.csv`/`metrics_val.csv` have exactly `n_splits * n_repeats` rows with a unique `(fold, repeat)` key, and the two files share the same key set; `history.csv` has a complete `1..n_epochs` epoch series per fold, `best_epoch` falls in that range, and the history value recorded at `best_epoch` for the run's `early_stopping_monitor` matches `best_monitor_value` within `1e-6` (with `restored_monitor_value` finite and within `1e-4` of it); `predictions_val.csv` has `y_true` in `{0,1}`, `y_prob` in `[0,1]`, no duplicate `subject_id` within a repetition, and full subject coverage per repetition; `folds.csv` has `fit`/`inner_val`/`outer_val` pairwise-disjoint within each fold; and `predictions_val.csv`'s subjects for a fold match `folds.csv`'s `outer_val` subjects for that same fold exactly, with partition sizes matching `n_fit`/`n_inner_val`/`n_outer_val` in `metrics_val.csv`.

Structural checks (column presence, finiteness, non-empty text fields) always run and are always reported before any semantic check starts: if any structural problem is found, the function returns immediately with that diagnostic instead of proceeding to compare files against each other on data it already knows is incomplete or corrupt. All of the semantic checks are additionally wrapped in a single `try/except (TypeError, ValueError, KeyError)` that turns any unanticipated content-corruption exception into an appended diagnostic string — a second layer of defense on top of the early return, for a case the structural checks don't happen to catch. `n_fit`/`n_inner_val`/`n_outer_val` are required structural columns on `metrics_train.csv`/`metrics_val.csv` (not just used later for the partition-size comparison); each of the five files has a unique-key check (`(repeat, fold)` for the metrics files, `(repeat, fold, epoch)` for `history.csv`, `(repeat, subject_id)` for `predictions_val.csv`, `(repeat, fold, subject_id)` for `folds.csv`) that catches duplicated rows sharing the same key; the same `(repeat, fold)` pair set found in `metrics_val.csv` is required to appear, with no additions or omissions, in `metrics_train.csv`, `history.csv`, `predictions_val.csv`, and `folds.csv` — catching a fold that is entirely missing from one of those files even though it's present in the others; and `folds.csv`'s `split` column is checked against `{fit, inner_val, outer_val}`, so an unrecognized value is reported instead of silently falling outside every partition set the rest of the checks look at.

The regression fixtures in `check_schema4_artifact_validation()` cover cases A through F. Case A: a valid schema-4 run (accepted, no problems). Case B: a structural column dropped from `predictions_val.csv`/`folds.csv`/`history.csv` (each detected individually; `collect(strict=True)` raises; `collect(strict=False)` drops the run and records the diagnostic instead of the row); case B2 does the same for `n_fit`/`n_inner_val`/`n_outer_val` dropped from `metrics_val.csv`. Case C: `NaN` injected into `best_monitor_value`, `inner_val_bce`, or `y_prob` in three independent subcases (each rejected). Case D: a schema-2 run (still compiles descriptively with the historical notice, not subjected to the schema-4 contract). Case E: nine cross-file mutations, one per subcase — a duplicated `subject_id` within a repetition, an incomplete OOF subject coverage, `y_prob` set outside `[0,1]`, a `fit`/`outer_val` overlap injected into `folds.csv`, a fold's predicted subjects renamed so they no longer match that fold's `outer_val` set, a duplicated row in `folds.csv`, a duplicated row in `history.csv`, a fold entirely removed from `metrics_train.csv` while still present in `metrics_val.csv`, and an unrecognized `split` value in `folds.csv` — each confirmed to make `validate_run_artifacts()` report a problem and `collect(strict=True)` raise a `ValueError` naming the affected run. Case F: `restored_monitor_value` set to a non-numeric string (`"abc"`) — `validate_run_artifacts()` must return a diagnostic list rather than let `np.isfinite()` raise `TypeError`, and `collect(strict=True)` must raise `ValueError` (not `TypeError`) over the same corrupted run.

As a meta-check, the Case A-D fixtures were also run against the pre-fix implementation to confirm they actually fail against the bug they target, rather than passing regardless of the code under test. The negative cases (B, B2, C, E, and F) also inspect the raised `ValueError`'s message rather than accepting any `ValueError`: it must name the affected run (and, for B/B2/C, the specific missing column or corrupted field), so an unrelated exception from elsewhere in `collect()` cannot be mistaken for this check having actually run — confirmed by forcing `collect()` to raise an unrelated `ValueError` and observing the assertion correctly fail instead of passing.

`check_aggregate_table_gate()` covers the companion safety check in `aggregate_table()`, with synthetic (non-CSV) rows rather than trained runs: it confirms `lr`, `arch_json`, and `deterministic` are among `methodological_group_columns()`; that two rows differing only in `lr` produce two separate aggregate rows instead of one averaged row; and that two rows identical in every grouped column but carrying different `config_hash` make `aggregate_table()` raise `SystemExit` naming both `run_id`s and both `config_hash`es, instead of silently averaging two configurations that share the columns it groups by but differ in something it doesn't. The same file repeats this pattern for the identity fields added to `methodological_group_columns()` for run-identity coverage — `representation_seed`, `start_from_epoch`, `random_subset`/`n_random_sets`, `seed`, and `runner_code_hash` — confirming each is both listed and actually used by `aggregate_table()` to keep otherwise-identical rows in separate groups; it also confirms software/GPU version fields (`tensorflow_version`, `gpu_name`, `python_version`) stay excluded from the grouping columns even when present in the input `DataFrame`, since those describe the execution environment rather than the run's methodological identity and are not part of `config_hash`.

`check_notebook_state_machine()` exercises the notebook's session state machine — `preflight()`, `prueba_humo()`, `ejecutar_corrida()`, `ejecutar_diagnostico_orden()`, and `exigir_corrida_validada()` — outside Colab, with a stand-in `run_experiment.main()` that returns a controllable run id or raises `SystemExit` instead of training. The relevant cells are extracted from `tdha_experimentos.ipynb` by cell id and executed in an isolated namespace seeded with a known-valid configuration (the same one documented in `guia-experimentacion-colaborativa.md`), so the test runs the notebook's real source rather than a hand-maintained copy that could drift from it. It checks: `preflight()` sets `PREFLIGHT_OK`/`PREFLIGHT_RUN_ID` on a clean `--dry-run` and raises `RuntimeError` (leaving `PREFLIGHT_OK` `False`) if `run_experiment.main()` reports a problem; `ejecutar_corrida()` refuses to run without a prior successful `preflight()`, and separately refuses to run if `EJECUTAR_PRUEBA_HUMO` is `True` but the smoke test hasn't passed; `prueba_humo()` raises `RuntimeError` and leaves `SMOKE_OK` `False` on a failed simulated training; a full happy path (`preflight()` → `prueba_humo()` → `ejecutar_corrida()`) succeeds and resets `CORRIDA_VALIDADA`/`RUN_ID_VALIDADO`; `ejecutar_corrida()` raises `RuntimeError` if the formal run's id doesn't match the one `preflight()` predicted (the configuration changed in between); `ejecutar_diagnostico_orden()` raises `ValueError` for a static representation and separately for `MODELO == "brainnetcnn"`; and `exigir_corrida_validada()` raises `RuntimeError` when `CORRIDA_VALIDADA` is `False`, raises when `RUN_ID_VALIDADO` doesn't match the current `RUN_ID` (a stale validation from an earlier run), raises and resets both flags when a revalidation against disk finds the run has changed since it was last validated, and passes through cleanly when the validation is current and the disk check finds nothing wrong.

## Evaluation and aggregation

Metrics are computed and exported with their configuration, so every run is traceable. Aggregation groups only comparable runs and keeps each one tied to its configuration.

## Reproducibility

Fixed seeds, exported configuration and metadata, and a standardized output layout let a run be repeated under the same settings.

## Improvements in this version

Physical (time-based) windowing with site-specific TR; static and dynamic connectivity; order-invariant and order-permuted representations for temporal-order controls; two Ledoit-Wolf shrinkage connectivity estimators (`partial`, `shrunk`) alongside raw Pearson; tangent-space connectivity (`tangent`, via nilearn) with a fold-local reference; per-fold rescaling controls (`ordered_scaled`, `permuted_scaled`) to separate a scaling effect from a representation effect; an architecture registry with six models, including an order-invariant baseline (`deepsets`) and a topological matrix model (`brainnetcnn`); shorter default early-stopping patience and optional mixed precision; a configurable early-stopping monitor (`val_loss`/`val_bce`, `config_schema_version=4`) that isolates whether selecting the epoch on predictive BCE alone, instead of total regularized loss, changes outcomes — without altering the optimized objective, with `best_epoch`/`best_monitor_value` sourced from the actual `EarlyStopping` instance (not reconstructed via `argmin`, which does not reproduce its semantics once `min_delta` or `start_from_epoch` are nonzero) and a non-circular restored-weights check (`restored_monitor_value`); an `early_stopping_ab_hash` (the run's full identity minus the monitor) that lets `compile_results.py --stats --stats-by early_stopping_monitor` require two runs to be identical in everything else before pairing them, instead of trusting a fixed list of columns; single-process batch execution; centralized configuration; standardized aggregation; per-repetition out-of-fold metrics; a Nadeau-Bengio corrected paired significance test for repeated k-fold comparisons, explicitly paired by `(repeat, fold)` rather than by row position; and `--strict-comparability` to fail instead of only warn when compiled runs are not comparable.
