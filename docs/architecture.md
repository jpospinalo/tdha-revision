# Software Architecture

The pipeline turns rs-fMRI ROI time series into connectivity representations and trains classifiers on them, keeping every run reproducible.

## Stages

```
ROI time series → data preparation → connectivity generation → cross-validated training → aggregation
```

Each stage consumes only the previous stage's output.

## Modules

**`data.py`** — loads ROI time series, builds static or dynamic connectivity, resolves the site-specific TR, cuts temporal windows from physical (seconds) specifications, and optionally applies a Fisher Z transform or Gaussian window weighting.

**`run_experiment.py`** — runs one experiment: builds the cross-validation folds, trains the model, selects the epoch on an inner split, evaluates on the outer fold, and writes the per-fold metrics, `config.json`, and a derived `resumen.md`. Most representations are built once, globally, before the fold loop. Three (`ordered_scaled`, `permuted_scaled`, `tangent`) instead go through a `fold_transform` hook that `run_config()` calls once per fold, fit only on that fold's `fit_idx` and applied without refitting to `inner_val`/`outer_val` — see `methodology.md`'s "Fold-local representations". When no `fold_transform` is given (every historical representation), the fold loop indexes the base tensor exactly as before. Epoch selection watches `--early-stopping-monitor` (`val_loss` by default, or `val_bce`), recorded in `config.json`'s identity; `best_epoch`/`best_monitor_value` come from the `EarlyStopping` instance itself, not from re-deriving the global minimum of the monitored series, and are corroborated by an independent post-`fit()` re-evaluation (`restored_monitor_value`), enforced with a `RuntimeError` before the outer fold is touched if it doesn't match `best_monitor_value` — see `methodology.md`'s "Early-stopping monitor".

**`run_queue.py`** — expands a grid of configurations and runs them, either as one subprocess per configuration or, with `--in-process`, all in a single process.

**`compile_results.py`** — collects the runs under `results/runs/<roi_set>/` (`12`/`18`/`39`/`116`, matching `run_experiment.py`'s `outdir`), and also under the legacy flat layout `results/runs/<run_id>/` for backward compatibility with runs saved before this ROI-subfolder split; `_find_run_dir()` centralizes that lookup for `paired_stats()`. It tabulates the collected runs, and warns when runs are not comparable (different seed, split fingerprint, BOLD hash, dirty git tree, or duplicated configs); `--strict-comparability` turns those warnings into a hard failure instead of just printing them. It also computes per-repetition out-of-fold metrics (pooling each repetition's fold predictions before scoring accuracy/AUC/F1/balanced-accuracy/log-loss/Brier — less noisy than averaging per-fold metrics). Paired comparisons (`--stats`) print a repeated-measures ANOVA labeled explicitly as exploratory — it treats folds as independent and does not correct for the overlap between a repeated k-fold's training sets, so it plays no role in the significance verdict. That verdict instead comes from a Nadeau-Bengio corrected resampled t-test (which does account for that overlap) plus Holm correction across contrasts; the naive paired t-test and Wilcoxon are kept in the output only as reference. Runs are paired by an explicit `(repeat, fold)` merge, not by position after sorting — it fails loudly on missing columns, duplicated keys within a run, or mismatched fold sets between runs, instead of silently pairing the wrong rows. `--stats-by` also accepts `early_stopping_monitor`, to pair two otherwise-identical runs that differ only in which series `EarlyStopping` watched — it requires both to share `early_stopping_ab_hash` (the run identity with only the monitor removed) and `config_schema_version >= 4`, rather than trusting a fixed list of columns to have caught every methodological difference. Before any of that pairing happens, `_check_stats_methodology(base, group_col)` requires every methodological field *other than* the requested `--stats-by` axis to be identical across the selected runs (training hyperparameters, architecture, `class_weight`, window parameters when applicable, code hashes, and so on — the exact set depends on `group_col`: comparing `roi_set` additionally fixes representation/window/monitor, comparing `representation` additionally fixes ROI identity and, when every compared representation uses windows, the window parameters too, and comparing `early_stopping_monitor` leaves the axis-specific guarantee to `early_stopping_ab_hash` above). It treats a column present in one run and missing (`NaN`) in another as a difference, not a coincidental match, and aborts with `SystemExit` — naming the offending field and every run's value — before `runs` is built or `paired_stats()` is called, even without `--strict-comparability`: a confounded contrast should fail closed, not print a caveated result. `--strict-comparability` keeps its separate, narrower job of gating `check_comparability()`'s provenance warnings (seed/split/BOLD mismatches, `git.clean=false`, duplicated configs) — `git.clean=false` is a provenance caveat surfaced there, never a methodological difference enforced by `_check_stats_methodology()`, so it cannot by itself trigger the new gate. `--strict-comparability` itself is unchanged and still fails closed on any dirty tree when passed; three historical exceptions (NeuroIMAGE-12 `2b729a8c`, OHSU-39 `299719fe`, Peking-12 `bc841110`) are documented in `results/README.md` as team-confirmed to have only touched `results/`/docs, not the runner, data, model, or training protocol, so their formal analyses run without that flag while still printing the warning — that documentation-level exception does not change `--strict-comparability`'s own conservative behavior. `methodological_group_columns()` — used by `--aggregate-out` — includes the architecture (as a canonical `arch_json`) and every training hyperparameter, not just site/ROI/model/representation, and `aggregate_table()` additionally aborts if a group it built still contains more than one `config_hash`, rather than averaging two configurations that share the grouping columns but differ in something else. `validate_run_artifacts(run_dir, suffix="", cfg=None)` is the public, single-folder validator for `config_schema_version >= 4` runs — `collect(strict=True)`, `verify_setup.py`, and the notebook's pre-export gate all call this one function instead of each keeping a partial copy of the checks.

**`kerasmodels/`** — the architecture registry. Each module registers a `build(n_windows, n_features, **hyperparameters)` that returns an **uncompiled** `keras.Model` with a single sigmoid output; `run_experiment.py` compiles it, so architectures carry no training hyperparameters. Registered:

- `lstm`, `gru` — recurrent, order-sensitive.
- `cnn1d` — 1D convolution along the window axis.
- `transformer` — self-attention; `positional=False` makes it order-invariant.
- `deepsets` — per-window MLP plus symmetric pooling, order-invariant by construction.
- `brainnetcnn` — edge-to-edge / edge-to-node filters over the connectivity matrix, which it reconstructs internally from the vectorized upper triangle. Works with any single-matrix representation (`static`, `partial`, `shrunk`, `mean`) and with `ordered`/`permuted`/their `_scaled` variants (windows as channels); incompatible with `mean_std`, `hybrid`, and `tangent` (see `limitations.md`).

A new module imported in `__init__.py` becomes available as `--model <name>`.

**`verify_setup.py`** — pre-flight checks after cloning: file structure, BOLD shapes, ROI-set consistency, sequence construction, cross-validation leakage, and that every architecture builds. With `--full`, it additionally trains BrainNetCNN exactly twice (`val_loss`/`val_bce`, sharing one root directory) to audit the early-stopping artifacts end to end, checks the default monitor via a pure parser call (no training), and feeds those same two runs into `compile_results.collect(..., strict=True)` and `_check_early_stopping_ab()` to confirm the compiler accepts the real pair and rejects a duplicated-monitor or altered-`early_stopping_ab_hash` variant — see `validation.md`.

## Design

Each module does one thing and hands standardized structures to the next, so a connectivity measure, representation, model, or metric can be swapped without touching the rest. Every run stores its full configuration next to its results — that is what makes runs reproducible and portable to other datasets with equivalent ROI time series.
